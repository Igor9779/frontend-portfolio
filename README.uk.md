# Фронтенд-портфоліо

Портфоліо Ігоря Бондаренка на Next.js App Router, React, TypeScript і Tailwind CSS. Supabase — єдине джерело даних для справжніх проєктів. Інтерфейс доступний англійською, українською та російською; вміст проєктів у CMS залишається мовою оригіналу.

## Маршрути

- `/` — публічне портфоліо з видимими проєктами у збереженому порядку та посиланням на інтерактивне демо CMS.
- `/admin` — захищена CMS для авторизованого адміністратора.
- `/admin/login` — вхід адміністратора; публічної реєстрації немає.
- `/cms-demo` — публічна локальна демонстрація CMS без входу.
- `/projects/*` — п’ять збережених окремих сайтів: LivesTopAir, PagesMaxAir, WorksAllsDay, PathsTopNow і WordsMaxLab.

## Справжня CMS

Додавайте, редагуйте, приховуйте й видаляйте проєкти. `create_project_first()` атомарно вставляє новий проєкт першим, зберігаючи взаємний порядок попередніх. Перетягування за ручку та доступні з клавіатури кнопки переміщення змінюють чернетку порядку. Збереження передає повний список у `reorder_projects()`, а скидання відновлює збережений порядок. Пошук вимикає впорядкування; незбережені зміни порядку блокують CRUD.

Текстові чернетки форми додавання, зокрема імпортовані значення, зберігаються в `sessionStorage` цієї вкладки. Закриття чи оновлення сторінки дає змогу відновити незавершений текст. Успішне створення, явне скидання або перехід на сторінку входу після підтвердженого сервером виходу очищує чернетку адміністратора. Файли та байти знімків до чернетки не потрапляють.

### Зображення

Для ручного завантаження підтримуються JPEG, PNG і WebP до 5 МБ; SVG відхиляється. Сервер перевіряє MIME, розширення та сигнатуру файлу. Зображення мають унікальні шляхи для кожного проєкту в публічному бакеті `project-previews`. Під час заміни спочатку зберігається нове посилання, потім видаляється старе кероване зображення. Помилка створення чи заміни запускає безпечне очищення; помилка очищення не скасовує успішне видалення запису з бази. Наявні зображення `/assets/...` підтримуються, локальні файли ніколи не видаляються.

### GitHub, AI та знімки сайтів

Імпорт із GitHub використовує публічний GitHub REST API без токена. Перевірені ідентифікатори репозиторію формують фіксовані API-адреси; метадані та назви мов заповнюють редаговані поля. Сам імпорт нічого не створює. Перевірка дублювання репозиторію виконується під час імпорту та остаточного створення.

Автозаповнення AI працює через серверний OpenAI Responses API з обмеженими метаданими, мовами, README та відомостями з package. Структуровані підказки замінюють лише назву, категорію, описи й технології. Їх можна редагувати; походження з GitHub, посилання, видимість і вибране зображення зберігаються. Відсутність налаштування або помилка провайдера не очищує форму. Запис з’являється лише після звичайного збереження чи створення.

Після імпорту з GitHub можна отримати тимчасовий знімок підтримуваного HTTPS-сайту. Повторний знімок використовує поточний URL сайту; ручний вибір файлу залишається доступним. `playwright-core` і `@sparticuz/chromium` створюють JPEG 1440 × 900 через доступний лише адміністратору Node.js Route Handler. Обмеження доменів хостингу, перевірка публічних DNS-адрес і CONNECT-проксі з фіксацією DNS унеможливлюють необмежене пересилання. Перевірка TLS залишається ввімкненою. Нові контексти браузера отримують мінімальне середовище без секретів застосунку. Створення знімка має часові обмеження, не використовує OpenAI, не змінює проєкти й не завантажує об’єкти Storage. Байти знімка стають браузерним File і проходять наявний шлях збереження зображення лише після натискання «Зберегти».

## Публічне демо CMS

Демо використовує вбудовані приклади проєктів і передбачувані локальні імітації GitHub → зображення → AI, зокрема приклад MUSE. Доступні локальні CRUD, видимість, зображення, додавання на початок списку, чернетка порядку та його збереження чи скидання. Імітації чітко позначені. Для непідтримуваного репозиторію показується зрозуміле повідомлення замість справжнього API-запиту.

Текст і порядок демо зберігаються в `sessionStorage` вкладки. Локальні файли залишаються на пристрої; непотрібні object URL звільняються, а після оновлення для файлів відновлюється резервне зображення. Скидання демо повертає початковий набір прикладів. Демо не може імпортувати справжні Server Actions, Auth, клієнти Supabase, OpenAI чи інфраструктуру знімків. Імітації не витрачають GitHub API, кошти на AI чи обчислення знімків і не змінюють робочі дані. Звичайні локальні ресурси та переходи за зовнішніми посиланнями доступні.

## Локалізація та доступність

Кнопки EN / UK / RU перемикають інтерфейс без перезавантаження. Перевірена мовна перевага з `localStorage` застосовується після гідратації; некоректні дані чи недоступне сховище обробляються безпечно. Мова документа відповідає інтерфейсу. Назви, описи, категорії, технології та URL із Supabase або демоприкладів не перекладаються й не змінюються.

Публічні сторінки, демо та інтерфейс адміністратора підтримують усі три мови. Збережено керування з клавіатури, видимий фокус, перехід до основного вмісту, підписи полів, фокус і Escape у діалогах та зменшення руху. Історичні окремі сайти навмисно не локалізуються й не змінюються.

## Модель безпеки

Cookie-сесії Supabase SSR визначають користувача. Кожна привілейована Server Action і запит знімка незалежно викликає `requireAdmin()`, перевіряючи особу та членство в `admin_users`. RLS бази й Storage та авторизація invoker RPC незалежно забезпечують той самий захист. Публічний ключ Supabase призначений для відкритого доступу; авторизація не залежить від його приховування. Ключа service-role, публічного створення облікових записів і браузерного клієнта для змін немає.

Глобальні заголовки забороняють вбудовування у фрейми, визначення типу вмісту браузером і доступ до камери, мікрофона та геолокації, а також обмежують передавання referrer. CSP обмежує лише фрейми, зберігаючи старі скрипти й стилі. Адміністративні маршрути не індексуються. Помилки й діагностика не містять облікових даних чи необроблених відповідей провайдерів. Локалізація зберігає лише мовну перевагу браузера й не додає серверних шляхів.

## Локальна розробка

Використовуйте Node.js 22.17+ або 24+. Встановіть залежності й скопіюйте порожній шаблон змінних:

```bash
npm install
cp .env.example .env.local
npm run dev
```

Налаштуйте ці назви змінних локально та в панелі хостингу; справжні значення ніколи не додавайте до git:

```dotenv
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=
OPENAI_API_KEY=
```

Перші дві змінні налаштовують публічний доступ до Supabase. `OPENAI_API_KEY` залишається на сервері й потрібен лише для справжніх AI-підказок адміністратора. Токен GitHub чи облікові дані сервісу знімків не потрібні. На macOS розробка знімків використовує вже встановлений сумісний Chrome/Chromium і ніколи не завантажує браузер під час запиту. Linux/Vercel використовує вбудований Chromium.

## Перевірка

```bash
npm test
npm run typecheck
npm run lint
npm run build
npm run check:screenshot-bundle
npm audit
git diff --check
```

Якщо локальний worker Turbopack не може прив’язати порт, використовуйте наявний шлях production-збірки Webpack:

```bash
npm run build -- --webpack
```

Автоматичні тести використовують моки й контрольовані приклади без платних викликів OpenAI або змін робочих даних. Тести графа імпортів забезпечують ізоляцію демо; авторизація, завантаження, порядок, AI-відповіді й SSRF-захист знімків мають регресійне покриття. Необов’язкові браузерні перевірки запускаються окремо:

```bash
node --test tests/cms-demo-browser.integration.mjs
node --test tests/localization-browser.integration.mjs
npm run test:screenshot-navigation
```

Приклади навігації знімків використовують лише локальний HTTPS і не знімають справжні сайти. Будь-яка реальна перевірка адміністратора потребує свідомого контролю й не повинна залишати тимчасових проєктів чи зображень.

## Розгортання та налаштування бази

Розгортайте як Node.js-застосунок Next.js на Vercel із тими самими назвами змінних і сумісним Node runtime. Зберігайте ресурси `public/`. Функція знімків залишає пакети браузера зовнішніми й явно включає ресурси Chromium та реєстр Playwright у trace; після production-збірки запускайте перевірку пакета. Для браузера потрібні Linux x86_64 і достатні пам’ять та тривалість функції. Локальна перевірка trace доповнює перевірку розгортання.

Файли `supabase/` описують наявні схему, дозволи, політики Storage та атомарні invoker RPC. SQL налаштування переглядається й застосовується вручну; скрипти перевірки лише читають дані, якщо не позначені як rollback-only. Не запускайте історичні скрипти наповнення чи перевірки без перегляду й не вимикайте RLS. Фінальні покращення інтерфейсу та локалізація не потребують міграції.

П’ять історичних сайтів у `public/projects/` зберігають початкові HTML, CSS, JavaScript і ресурси. Каталог проєктів змінюється в захищеній CMS, а не у жорстко заданих даних портфоліо.
