# Фронтенд-портфолио

Портфолио Игоря Бондаренко на Next.js App Router, React, TypeScript и Tailwind CSS. Supabase — единственный источник данных для настоящих проектов. Интерфейс доступен на английском, украинском и русском; содержимое проектов в CMS остаётся на языке оригинала.

## Маршруты

- `/` — публичное портфолио с видимыми проектами в сохранённом порядке и ссылкой на интерактивное демо CMS.
- `/admin` — защищённая CMS для авторизованного администратора.
- `/admin/login` — вход администратора; публичной регистрации нет.
- `/cms-demo` — публичная локальная демонстрация CMS без входа.
- `/projects/*` — пять сохранённых отдельных сайтов: LivesTopAir, PagesMaxAir, WorksAllsDay, PathsTopNow и WordsMaxLab.

## Настоящая CMS

Добавляйте, редактируйте, скрывайте и удаляйте проекты. `create_project_first()` атомарно вставляет новый проект первым, сохраняя относительный порядок предыдущих. Перетаскивание за ручку и доступные с клавиатуры кнопки перемещения меняют черновик порядка. Сохранение передаёт полный список в `reorder_projects()`, а сброс восстанавливает сохранённый порядок. Поиск отключает упорядочивание; несохранённые изменения порядка блокируют CRUD.

Текстовые черновики формы добавления, включая импортированные значения, сохраняются в `sessionStorage` этой вкладки. Закрытие или обновление страницы позволяет восстановить незавершённый текст. Успешное создание, явный сброс или переход на страницу входа после подтверждённого сервером выхода очищает черновик администратора. Файлы и байты снимков в черновик не попадают.

### Изображения

Для ручной загрузки поддерживаются JPEG, PNG и WebP до 5 МБ; SVG отклоняется. Сервер проверяет MIME, расширение и сигнатуру файла. Изображения имеют уникальные пути для каждого проекта в публичном бакете `project-previews`. При замене сначала сохраняется новая ссылка, затем удаляется старое управляемое изображение. Ошибка создания или замены запускает безопасную очистку; ошибка очистки не отменяет успешное удаление записи из базы. Существующие изображения `/assets/...` поддерживаются, локальные файлы никогда не удаляются.

### GitHub, AI и снимки сайтов

Импорт из GitHub использует публичный GitHub REST API без токена. Проверенные идентификаторы репозитория формируют фиксированные API-адреса; метаданные и названия языков заполняют редактируемые поля. Сам импорт ничего не создаёт. Проверка дублирования репозитория выполняется при импорте и окончательном создании.

Автозаполнение AI работает через серверный OpenAI Responses API с ограниченными метаданными, языками, README и сведениями из package. Структурированные подсказки заменяют только название, категорию, описания и технологии. Их можно редактировать; происхождение из GitHub, ссылки, видимость и выбранное изображение сохраняются. Отсутствие настройки или ошибка провайдера не очищает форму. Запись появляется только после обычного сохранения или создания.

После импорта из GitHub можно получить временный снимок поддерживаемого HTTPS-сайта. Повторный снимок использует текущий URL сайта; ручной выбор файла остаётся доступным. `playwright-core` и `@sparticuz/chromium` создают JPEG 1440 × 900 через доступный только администратору Node.js Route Handler. Ограничение доменов хостинга, проверка публичных DNS-адресов и CONNECT-прокси с фиксацией DNS предотвращают неограниченную пересылку. Проверка TLS остаётся включённой. Новые контексты браузера получают минимальное окружение без секретов приложения. Создание снимка ограничено по времени, не использует OpenAI, не изменяет проекты и не загружает объекты Storage. Байты снимка становятся браузерным File и проходят существующий путь сохранения изображения только после нажатия «Сохранить».

## Публичное демо CMS

Демо использует встроенные примеры проектов и предсказуемые локальные имитации GitHub → изображение → AI, включая пример MUSE. Доступны локальные CRUD, видимость, изображения, добавление в начало списка, черновик порядка и его сохранение или сброс. Имитации явно обозначены. Для неподдерживаемого репозитория показывается понятное сообщение вместо настоящего API-запроса.

Текст и порядок демо сохраняются в `sessionStorage` вкладки. Локальные файлы остаются на устройстве; ненужные object URL освобождаются, а после обновления для файлов восстанавливается резервное изображение. Сброс демо возвращает исходный набор примеров. Демо не может импортировать настоящие Server Actions, Auth, клиенты Supabase, OpenAI или инфраструктуру снимков. Имитации не расходуют GitHub API, средства на AI или вычисления снимков и не изменяют рабочие данные. Обычные локальные ресурсы и переходы по внешним ссылкам доступны.

## Локализация и доступность

Кнопки EN / UK / RU переключают интерфейс без перезагрузки. Проверенное языковое предпочтение из `localStorage` применяется после гидратации; некорректные данные или недоступное хранилище обрабатываются безопасно. Язык документа соответствует интерфейсу. Названия, описания, категории, технологии и URL из Supabase или демопримеров не переводятся и не изменяются.

Публичные страницы, демо и интерфейс администратора поддерживают все три языка. Сохранены управление с клавиатуры, видимый фокус, переход к основному содержимому, подписи полей, фокус и Escape в диалогах и уменьшение движения. Исторические отдельные сайты намеренно не локализуются и не изменяются.

## Модель безопасности

Cookie-сессии Supabase SSR определяют пользователя. Каждая привилегированная Server Action и запрос снимка независимо вызывает `requireAdmin()`, проверяя личность и членство в `admin_users`. RLS базы и Storage и авторизация invoker RPC независимо обеспечивают ту же защиту. Публичный ключ Supabase предназначен для открытого доступа; авторизация не зависит от его сокрытия. Ключа service-role, публичного создания аккаунтов и браузерного клиента для изменений нет.

Глобальные заголовки запрещают встраивание во фреймы, определение типа содержимого браузером и доступ к камере, микрофону и геолокации, а также ограничивают передачу referrer. CSP ограничивает только фреймы, сохраняя старые скрипты и стили. Административные маршруты не индексируются. Ошибки и диагностика не содержат учётных данных или необработанных ответов провайдеров. Локализация сохраняет только языковое предпочтение браузера и не добавляет серверных путей.

## Локальная разработка

Используйте Node.js 22.17+ или 24+. Установите зависимости и скопируйте пустой шаблон переменных:

```bash
npm install
cp .env.example .env.local
npm run dev
```

Настройте эти названия переменных локально и в панели хостинга; настоящие значения никогда не добавляйте в git:

```dotenv
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=
OPENAI_API_KEY=
```

Первые две переменные настраивают публичный доступ к Supabase. `OPENAI_API_KEY` остаётся на сервере и нужен только для настоящих AI-подсказок администратора. Токен GitHub или учётные данные сервиса снимков не нужны. На macOS разработка снимков использует уже установленный совместимый Chrome/Chromium и никогда не загружает браузер во время запроса. Linux/Vercel использует встроенный Chromium.

## Проверка

```bash
npm test
npm run typecheck
npm run lint
npm run build
npm run check:screenshot-bundle
npm audit
git diff --check
```

Если локальный worker Turbopack не может привязать порт, используйте существующий путь production-сборки Webpack:

```bash
npm run build -- --webpack
```

Автоматические тесты используют моки и контролируемые примеры без платных вызовов OpenAI или изменений рабочих данных. Тесты графа импортов обеспечивают изоляцию демо; авторизация, загрузки, порядок, AI-ответы и SSRF-защита снимков имеют регрессионное покрытие. Необязательные браузерные проверки запускаются отдельно:

```bash
node --test tests/cms-demo-browser.integration.mjs
node --test tests/localization-browser.integration.mjs
npm run test:screenshot-navigation
```

Примеры навигации снимков используют только локальный HTTPS и не снимают настоящие сайты. Любая реальная проверка администратора требует осознанного контроля и не должна оставлять временных проектов или изображений.

## Развёртывание и настройка базы

Развёртывайте как Node.js-приложение Next.js на Vercel с теми же названиями переменных и совместимым Node runtime. Сохраняйте ресурсы `public/`. Функция снимков оставляет пакеты браузера внешними и явно включает ресурсы Chromium и реестр Playwright в trace; после production-сборки запускайте проверку пакета. Для браузера нужны Linux x86_64 и достаточные память и длительность функции. Локальная проверка trace дополняет проверку развёртывания.

Файлы `supabase/` описывают существующие схему, разрешения, политики Storage и атомарные invoker RPC. SQL настройки проверяется и применяется вручную; скрипты проверки только читают данные, если не помечены как rollback-only. Не запускайте исторические скрипты наполнения или проверки без просмотра и не отключайте RLS. Финальные улучшения интерфейса и локализация не требуют миграции.

Пять исторических сайтов в `public/projects/` сохраняют исходные HTML, CSS, JavaScript и ресурсы. Каталог проектов изменяется в защищённой CMS, а не в жёстко заданных данных портфолио.
